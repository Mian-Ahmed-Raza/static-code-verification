# Code Review Report


| Line Number | Defect Type | Why It Is a Problem | Proposed Fix | Severity |
|-------------|-------------|----------------------|---------------|----------|
| 35 | Assignment in conditional (`=` instead of `==`) | `if (monsters[i]->id = id)` assigns `id` to `monsters[i]->id` instead of comparing, corrupting data and always evaluating truthy unless `id == 0`. | Change `=` to `==`. | Critical |
| 40, 54, 64 | Missing null pointer check | `findMonster()` can return `nullptr`; the returned pointer `m` is dereferenced without checking, causing undefined behavior/crash. | Check `if (m == nullptr)` and handle gracefully before use. | Critical |
| 41–42 | Signed/unsigned mismatch | `unsigned int dmg = damage;` then `m->health - dmg < 0` is always evaluated in unsigned arithmetic, so the condition never behaves as intended, allowing incorrect health values. | Keep all arithmetic in signed `int`, or explicitly check `damage > m->health` before subtracting. | High |
| 48 | Off-by-one loop bound | `for (int i = 0; i <= monsterCount; i++)` accesses `monsters[monsterCount]`, which is out of bounds / uninitialized. | Change condition to `i < monsterCount`. | Critical |
| 53–56 | Returning reference to local variable | `label` is a local `std::string`; returning a reference to it produces a dangling reference once the function returns. | Change return type to `std::string` (return by value). | Critical |
| 59 | Uninitialized variable | `double sum;` is used in accumulation without initialization, producing garbage/undefined results. | Initialize as `double sum = 0.0;`. | High |
| 61 | Division by zero | `sum / monsterCount` will divide by zero if no monsters exist. | Add a check: `return monsterCount == 0 ? 0 : sum / monsterCount;`. | Medium |
| 64–66 | Use-after-free | `delete m;` is called, then `m->name` is accessed immediately after deletion — undefined behavior. | Print/store monster name *before* calling `delete`, and remove the pointer from the array/mark it as `nullptr`. | Critical |
| 64–66 | Dangling pointer left in container | After deleting `m`, the pointer remains inside `monsters[]`, causing a double-delete later in the destructor. | Remove the pointer from `monsters[]` (e.g., shift remaining elements or set slot to `nullptr` and skip it in loops). | Critical |
| 74–77 | Missing return statement | `playerRank()` has no `return` for the `score <= 100` case; falling off the end of a non-void function is undefined behavior. | Add a final `else return 3;` (or appropriate default). | High |
| 80, 83 | Unsafe fixed-size buffer | `char* name = new char[10];` combined with `std::cin >> name` has no bound on input length, risking a buffer overflow. | Use `std::string name; std::cin >> name;` instead of a raw buffer. | Critical |
| 87 | Mismatched delete/new | Allocated with `new char[10]` (array) but freed using `delete name;` instead of `delete[] name;` — undefined behavior. | Change to `delete[] name;` (or avoid raw pointers entirely as per fix above). | High |
| 29–32, 97 | No array bounds check | `spawnMonster()` doesn't verify `monsterCount < MAX_MONSTERS` before inserting; spawning a 6th monster (Line 97) overflows the `monsters[]` array. | Add a capacity check: `if (monsterCount >= MAX_MONSTERS) return;` (or throw/log). | Critical |
| 98 | Memory leak | `Monster* bonus = new Monster(...)` is never deleted or added to any container that manages its lifetime. | Either add `bonus` to the `Game` via `spawnMonster`, or delete it when no longer needed, or use a smart pointer. | Medium |
| 99 | Invalid argument to function call | `game.attackMonster(99, 20)` uses a monster ID that doesn't exist, causing `findMonster()` to return `nullptr`, which is then dereferenced. | Validate ID exists before calling, or handle `nullptr` return inside `attackMonster()`. | Critical |
| 107 | Missing copy constructor / shallow copy | `Game copy = game;` uses the compiler-generated copy constructor, which does a shallow copy of the `Monster*` array; both `game` and `copy` will attempt to `delete` the same pointers in their destructors (double free). | Implement a proper deep-copy constructor and assignment operator for `Game`, or disable copying (`= delete`), or use smart pointers (`std::unique_ptr`/`std::shared_ptr`). | Critical |
| 71 | Integer truncation before conversion | `attack * armorPercent / 100` is computed using integer arithmetic before being implicitly converted to `double`, losing precision. | Cast explicitly: `return (static_cast<double>(attack) * armorPercent) / 100.0;`. | Low |
